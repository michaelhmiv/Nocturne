# Nocturne revival: Jev-native implementation and certification register

## Product contract

The standalone website is the primary client. Players use natural language to inhabit a persistent alternate-real New York City built from real geography plus fictional people, businesses, interiors, incidents, and property details. ChatGPT/MCP remains an optional client of the same authoritative API.

Ordinary humans may attempt arbitrary plausible actions. Superpowers are excluded. The core loop is explore/interact, earn/spend, acquire assets and skills, build relationships/reputation, and cause/respond to trouble. New players receive a dynamically provisioned bare-bones starter apartment in a lower-income district. NPCs are stationary but reactive at launch. Elections, cosmetics, and autonomous long-horizon NPC ambitions remain deferred.

Characters and property remain vulnerable offline. Defeat uses accelerated GTA-style recovery while theft, damage, legal consequences, lost property, money, and reputation persist. The approach/keep-to-self preference affects voluntary ambient social approaches only and never grants immunity. Encounters depend on authoritative location, routes, visibility, access, and timing. Missed response windows use a standing self-preservation policy: escape when feasible, surrender when cornered, and never default to fighting to the death.

Only reported/public evidence may enter the newspaper. An unidentified robbery may be reported without identifying the offender; undiscovered acts remain unpublished. Narration, status, map, history, newspaper, and other players' views must agree with committed world state.

## Non-negotiable runtime architecture

The production player-command path is:

```text
player natural language
  -> deterministic context/candidate compiler
  -> Jev typed semantic decisions
  -> versioned engine-readable semantic packet
  -> deterministic validation / rules / rolls / clocks / database commit
  -> committed player-safe facts
  -> Laguna XS plain-text narration
  -> deterministic hard safety checks
  -> player
```

### Jev owns semantic interpretation

Jev converts messy human language and supplied context into bounded machine-readable decisions. It may choose only supplied/allowlisted values. Typical outputs include:

- detailed action type;
- referenced persistent entity IDs and semantic roles;
- clarification need;
- compound/multi-step structure;
- semantic categories such as consumable type, search target family, reaction class, evidence class, severity band, or newsworthiness;
- bounded relative scores where deterministic mechanics need semantic judgment.

Jev never writes authoritative state.

### The engine owns reality

Deterministic code and PostgreSQL own:

- location, access, visibility, route connectivity, presence, quantity, possession, ownership, and inventory;
- money, prices, transfers, balances, and resource conservation;
- clocks, schedules, travel progress, work duration, response windows, and offline continuation;
- random rolls, contest resolution, damage application, injury state, death/incapacitation, recovery, arrest/custody, legal state, and reputation mutation;
- idempotency, concurrency, atomic commits, event receipts, and replay;
- whether a proposed semantic action is physically/legal-system valid.

Decision confidence is never gameplay success probability.

### Laguna XS owns presentation only

Laguna XS receives committed player-visible/public facts after the engine has resolved and committed reality. It returns plain text only. No JSON schema or structured-generation protocol is used for narration.

Laguna may add harmless connective phrasing and stylistic variability. It may not materially change game reality. A deterministic narrator is always available if the narration provider fails or violates a hard safety invariant. No second narration model is used as a runtime fallback.

### No generative planner on the player-action path

A normal generative model must not interpret or plan player commands. If Jev cannot confidently map a statement into an engine-readable semantic packet, the valid outcomes are:

1. ask another bounded Jev question;
2. ask the player for clarification; or
3. reject the interpretation as insufficiently specified.

Do not send the original player command to Qwen, Laguna, or another generative planner.

## Universal testing standard

Every implementation PR must include all applicable layers below. A PR is not complete because unit tests pass.

### Required deterministic gates

1. **Type/static:** TypeScript typecheck, schema validation, workflow syntax/lint, migration integrity.
2. **Unit:** happy path, boundary conditions, malformed input, low-confidence/clarification path, invariant rejection, and deterministic fallback.
3. **Contract:** every public API and semantic packet is parsed through its runtime schema; version compatibility is tested.
4. **Database:** real PostgreSQL migrations plus reads/writes against a fresh database and upgrade-from-prior schema where the PR changes persistence.
5. **Concurrency/idempotency:** simultaneous duplicate requests, conflicting payloads, retries after timeout, process restart, and cross-world isolation for every mutation path.
6. **Integration:** compiled API with deterministic fake Jev/Laguna providers and real PostgreSQL.
7. **Action matrix:** representative commands across every affected action class, including inaccessible/absent/insufficient-resource cases.
8. **Browser:** website flow on desktop and mobile for user-visible changes.
9. **Security/privacy:** prompt injection, hidden-fact leakage, opaque-ID leakage, cross-user/world isolation, and secret/log sanitization.
10. **Regression:** previously certified action suites continue to run unchanged.

### Required live-model gates for AI-facing work

Trusted GitHub Actions using `OPENROUTER_API_KEY` must run:

- Jev typed-interface contract against `~typesafe/jev-latest`;
- held-out semantic corpus with per-field accuracy, invalid rate, clarification accuracy, role-selection precision/recall, p50/p95/p99 latency, and cost;
- Laguna XS plain-text narration corpus with valid-response rate, hard-invariant violations, prose-quality samples, p50/p95/p99 latency, and cost;
- adversarial prompt-injection cases;
- provider timeout/429/5xx behavior and deterministic fallback behavior.

Live-provider failures are failures, never silent passes.

### Required simulation/adversarial gates

For systems affecting persistent world state, generate long randomized sequences and assert invariants after every commit:

- no negative/duplicated money or inventory;
- one authoritative owner/location where required;
- inaccessible entities cannot be physically used;
- route/location/time cannot contradict;
- incapacitated/dead/custodied actors cannot perform prohibited actions;
- hidden evidence cannot leak to player/news views;
- newspaper identity claims require public identity evidence;
- map/status/history/narration agree with committed state;
- retry/replay does not duplicate consequences.

Failures must upload sanitized traces, seeds, provider outputs, SQL diagnostics, browser screenshots, and relevant artifacts.

## Final architectural acceptance test

Two questions decide whether a feature belongs in the correct layer:

1. **Could the engine understand and execute the player's intention if Laguna did not exist?**  
   The answer must be yes.

2. **Could Laguna change what actually happened?**  
   The answer must be no.

The game must remain mechanically correct if Laguna is replaced by deterministic text. Jev output must remain bounded and machine-readable enough that the engine never has to infer player intent from prose after the semantic boundary.
